1. SÉCURITÉ DU PROJET

La sécurité a été prise en compte tout au long du développement du projet
« Trouve ton artisan ! », aussi bien au niveau du frontend que du backend.

1.1 Protection contre les injections SQL

Les requêtes SQL utilisent des paramètres préparés afin de séparer les données
fournies par l'utilisateur de la requête SQL.

Exemple :

const [rows] = await db.query(
    "SELECT * FROM artisans WHERE id = ?",
    [id]
);

Cette méthode permet de limiter les risques d'injection SQL.

1.2 Validation des données

Les données provenant du formulaire de contact sont contrôlées côté serveur.

Le backend vérifie notamment :
- la présence de tous les champs obligatoires ;
- le format de l'adresse email ;
- la longueur du nom ;
- la longueur de l'objet ;
- la longueur du message.

Cette validation empêche l'enregistrement de données invalides ou excessivement
longues.

1.3 Protection des en-têtes HTTP avec Helmet

Le backend utilise la bibliothèque Helmet.

Exemple :

app.use(helmet());

Helmet permet de configurer plusieurs en-têtes HTTP de sécurité et d'améliorer
la protection du serveur web.

1.4 Limitation du nombre de requêtes

Le projet utilise express-rate-limit.

Exemple :

const apiLimiter = rateLimit({
    windowMs: 15 * 60 * 1000,
    max: 100
});

Cette protection limite le nombre de requêtes pouvant être envoyées à l'API
pendant une période donnée et permet de limiter certains abus.

1.5 Limitation de la taille des requêtes

La taille des données JSON reçues par le serveur est limitée :

app.use(express.json({ limit: "10kb" }));

Cela permet d'éviter la réception de requêtes inutilement volumineuses.

1.6 Configuration CORS

Le serveur utilise CORS afin de contrôler les origines autorisées à accéder
à l'API.

En développement, le frontend React est autorisé depuis :

http://localhost:5173

En production, cette origine devra être remplacée par l'adresse réelle du
site hébergé.

1.7 Protection des informations sensibles

Les informations de connexion à la base de données sont stockées dans le
fichier .env.

Le fichier .env est exclu du dépôt Git grâce au fichier .gitignore.

Les identifiants de connexion ne sont donc pas présents dans le code source
publié sur GitHub.

1.8 Gestion des erreurs

Les erreurs serveur sont interceptées et une réponse générique est renvoyée
au client.

Exemple :

res.status(500).json({
    message: "Une erreur interne est survenue"
});

Cela évite d'exposer au navigateur des informations techniques internes.

1.9 Validation côté frontend

Le formulaire utilise également la validation HTML avec les attributs
required et type="email".

Cette validation permet de détecter rapidement certaines erreurs avant
l'envoi des données au serveur.

La validation côté frontend est complétée par une validation côté backend.
